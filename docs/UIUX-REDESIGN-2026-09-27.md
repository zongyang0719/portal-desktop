# Being Desktop · 重设计总纲与实施记录

日期：2026-09-27。状态：已补齐全量功能与交互审查；第一轮源码改动仅为局部试验，尚未得到整体设计认可或真实客户端视觉验收。

本次完整范围见 [Desktop 全量功能与交互图谱](ux-audit-desktop-full-2026-09-27.md)：14 组、73 个面板／交互单元、20 条完整流程，逐项记录当前实现、重设计规则、状态归属、返回与失败恢复，并列出 14 个有源码证据的问题。用户举出的私信、安装往返、圆角、场景信息只是例子；后续按全量图谱推进，不能将本文件早先列出的几个主流程当成全部范围。视觉原则仍结合最新 spec。

审查修正：普通未发送草稿尚未持久化；排队提示与取消尚未接入消息正文；聊天选文引用的回来源存在 message ID／turn ID 不匹配。第一轮测试和局部预览没有证明这些全局行为通过。以下保留当时的设计与实现记录，冲突处以全量图谱和当前源码为准。

## 需求与产品立场

Being 是持续的伙伴。Desktop 让人接续关系、讨论、共同阅读、委托行动、看结果和经历。左侧组织场景，中间持续对话，右侧呈现当前在看的内容与操作。保留已有能力，重新组织流程、层级、反馈与细节。

优先保证五件事：不用离开原文就能讨论；返回能回到原位置；草稿和引用各有归属；下一步明确；状态有真实依据。安静来自主次分明，不靠藏掉必需入口。

## 参考与取舍

- [Linear 2026 年界面更新](https://linear.app/now/behind-the-latest-design-refresh)：统一位置栏与操作栏、弱化导航、柔化边界。借鉴布局纪律，不移植项目管理密度或状态配色。
- [Dia 的上下文分组](https://www.diabrowser.com/release-notes/1-14-0-meeting-tab-groups)：显式把所看内容带进对话。借鉴上下文连接，不把对话挤到右侧。
- [Craft 的桌面层级](https://www.craft.do/blog/craft-update-3-6-5)：侧栏落在窗口底面，中央文档突出。借鉴前后层次，不移植装饰性玻璃。
- 本地 native-feel 的 T3 / T7：沿用平台输入、窗口和快捷键习惯。继续使用现有 Electron 与 React，不为视觉改版更换运行架构。

比较过三种组织：全屏栏目切换会中断讨论；多浮窗会造成焦点和层级争夺；默认并排协作最符合已确认需求。采用并排，保留主动放大阅读的方式。窄窗口可以切换正在看的区域，但不销毁隐藏区域状态。

## 三栏的职责与视觉

- 左：场景列表、场景管理和活动。当前场景名与信息入口一直可見，更多动作渐进展开。新建、选中、重命名、多选仍使用熟悉操作。
- 中：与你的 Being 对话。标题与操作处于稳定位置，正文在独立阅读面内，输入始终可用。工具过程默认简明摘要，能展开核查。
- 右：私信、围炉、文档、工具库、浏览器等内容。标题说明在哪里，后退说明回到哪里，关闭仅收起内容。切换右侧不会替换中间场景或草稿。
- 中间阅读面使用约 14px 圆角、细描边、8–12px 外部留边；圆角属于内容面，不模拟第二个系统窗口，不添加假交通灯。
- 亮色使用中性浅灰窗口底面和更明亮的内容面；暗色使用相邻灰阶。正文、辅助文字、边界各自有对比度，不用降低整块 opacity 制造层级。
- 系统字体；正文随阅读字号设置，操作标签统一字号与图标光学尺寸。按钮热区至少 28–32px，正文可选、界面标签不可选。
- 不持续播放装饰动画。展开/收起保持方向清楚，尊重减少动态；布局变化不阻断输入。

## 第一轮计划所列主流程

| 场景 | 目标流程 | 保留与返回规则 |
|---|---|---|
| 打开与回来 | 恢复最近场景与阅读现场；首次连接有单一明确入口；有依据时提供上次进度及新的主动消息 | 切回窗口不强制经过欢迎页；无新动态时不虚构摘要 |
| 场景切换 | 选择场景即进入对应对话；名字旁常驻信息；管理操作仍在清晰菜单中 | 各场景保留草稿、附件、引用；删除列表条目不冒充删除远端历史 |
| 看私信并讨论 | 右侧打开消息 → 一起看 → 引用进入中间输入框 → 人写要求 → 发给 Being → 对照原文讨论 | 原消息不关闭、不跳顶；引用能展开、移除、回出处；移除引用不删文字或附件 |
| 发送 Town 回复 | 右侧“回复”直接写最终正文；“让 Being 回复”明确会委托拟写并发布；想先商量用“一起看” | 发送范围、当前代发身份可见；交给 Being 与 Town 发布成功分别反馈；讨论不能偷偷变成发布 |
| 阅读书架、卷轴、花园 | 列表 → 详情 → 分段阅读 / 相关条目 → 一起看 / 链接 | 保存筛选、页码、对象与阅读位置；公开/私有/成员可见继续分清 |
| 安装工具 | Grove 详情 → 说明能力、依赖与必要配置 → 安装进度 → 结果 → 继续浏览 / 查看本机 Kit | 取消回原详情；失败原位重试并保留填写内容；成功不自动带离来源；从本机详情能回原 Grove 详情 |
| 安装后使用 | 确认本机文件和 Portal 加载状态 → 在主对话提出使用要求 | “已安装”不等于“已验证可用”；没有真实状态时不显示可用或自动执行试验 |
| 本机 Kit 管理 | 本机列表 → 详情 → 查看工具 / 目录 / 配置 / 删除 | 删除说明范围并确认；失败不从列表假装消失；不影响 Grove 发布条目 |
| Town 身份与连接 | 当前身份 → 配对或修复 → 成功后返回发起操作 | 保留能安全保留的阅读现场；身份改变清理旧身份私有数据；不把对话名字当成 Town 已配对证明 |
| SBS 与主动活动 | Being 稳定入口 → 查看活动依据 → 操作自主醒来开关 | 开关、应用中、失败和活动状态分开；连接不等于思考；不假造情绪或经历 |
| 做事与后台任务 | 提出要求 → 看正在做什么 → 需要时展开 → 回到结果 | 排队、执行、等待 Being 回复、失败、停止各有文案；完成对应场景不抢当前阅读 |
| 浏览器 | 在右侧看网页、开链接，必要时回来源 | 地址和页面导航独立；不声称打开页面即被 Being 感知；完整共享须有真实接口 |
| 设置与维护 | 稳定入口 → 分类 → 子页 → 返回同一设置分类或原工作现场 | 区分客户端自启、Portal 常驻、SBS；保存失败保留输入；模型与 subagent 设置分开 |
| 共同物件与搁置 | 从有来源的对话 / 内容形成物件；暂放后随时找回 | 需要真实存储与接口后接入；不把示例物件或本地快照包装成 Being 记忆 |

## 组件与状态约定

1. 导航状态属于阅读面，草稿属于对话场景，安装状态属于安装事务；互不清空。
2. 引用有稳定来源、摘录快照与独立移除操作。重复添加同段不复制，多个引用有清楚边界。发送固定当次引用，后选内容不混入在途请求。
3. 请求中不离开原处；失败紧邻操作，提供可执行的重试；成功展示真实完成范围和下一步。
4. 关闭浮层回到发起控件；Esc 先关闭最上层；右侧面板可关闭但不得清空主对话。
5. 读私信时可持续输入和查看 Being 回答；打开需要提交配置的对话框时才短暂阻断操作。长时间后台安装后续移入右侧事务视图，避免模态等待。
6. 右侧导航统一保存当前位置。第一轮覆盖协作时不离开原文及 Kit 安装往返；后续把跨栏目、相关内容、浏览器入口纳入同一导航历史，不能宣称已完成全局恢复。

## 全量实施顺序与验收

此前第一轮只覆盖主框架、引用与 Kit 局部往返，记录保留在下节。后续按下列依赖顺序覆盖全部面板，细项、发现编号及验收门槛见全量图谱第 11 节：

1. 先保护工作：草稿恢复、队列呈现、停止回执、身份和引用定位。
2. 统一空间：右侧导航历史、浏览器容器、设置返回、覆盖层和本地已读规则。
3. 完整交流：篝火、围炉、私信的阅读与书写，讨论与委托分开，配对续接、通讯录与通知。
4. 完整阅读：花园、派生关系、经验墙、书架、卷轴、公告及其连续往返。
5. 完整本机能力：Grove、安装、导入、删除、本机 Kit、Portal 与诊断。
6. 完整维护：所有设置及模型子页、Being／SBS 入口、帮助、更新、退出和重启恢复。
7. 补齐能力后接入：冷启动连续性、真实存在事件、共同物件和搁置。

每批同时处理结构、视觉、加载、空态、失败、返回、键盘、长文本、亮暗与辅助技术，不把这些细节全部推到最后。记录打开前在何处、触发何动作、读写何内容、等待时能做什么、成功／失败如何回来、草稿和阅读位置是否保留。重要改动展示实际运行效果，收到用户反馈再推进下一批。构建通过不等于视觉验收。

## 第一轮交付与验证

预览：`demo/collaboration.html`；生成命令 `npm run build:collaboration-demo`。直接复用正式组件；对话内容、传输与安装使用隔离的示例适配，没有访问真实账户。

已实现：中间内容面圆角与留边、常驻场景信息、默认并排；右侧标题菜单取代重复平铺的栏目栏；主对话每个场景的引用独立保存在内存、展开、删除，Town 引用有局部来源恢复；一起看不关闭原文、不替换草稿或附件；安装后明确选择下一步，并从本机 Kit 返回原 Grove 详情、筛选与滚动位置。引用加入不自动发送；Town 保留直接发送与委托发布两个动作。后续全量审查确认，聊天选文的回来源未正确贯通，回复输入也仍混用正文与给 Being 的要求；不能将第一轮理解为这两项已完成。

## 第二轮实现：三栏导航与阅读层级

用户确认“基本上就是左中右，注意层级，不遗漏 Being 的理解”后，已将主导航迁入复用的左侧栏。Being 和场景、中间持续对话、右侧小镇内容形成独立层级；移除 Desktop 输入区的重复小镇菜单。

本轮还将回复编辑器放进右栏，区分正文与委托要求；栏目记住阅读现场，浏览器复用同一右侧区域，安装结果可返回来源。实现与验证细节见 [三栏导航重构实施记录](UIUX-NAVIGATION-REFACTOR-2026-09-27.md)。本轮 162 项相关测试、类型检查及构建通过；真实客户端原生视觉验收仍待进行，全功能审计表中的后续项不因此被标记完成。
