# Codex 任务：桌面客户端修正轮——恢复色彩语义，其余不动

## 背景

上一轮你把客户端往「安静」方向改：布局重组（功能栏＋场景列表＋内容＋对话分栏）、place 默认右栏、导航分组、主题跟随系统。**这个骨架是对的，本轮全部保留，一概不许动。**

但有两处越界造成了功能损伤，本轮只修这两处。

## 你犯的错：把「安静」理解成了「去色」

你在 `desktop/renderer/app/styles.css` 里把所有功能色改成了灰色。安静的正确含义是**层级、留白、字阶**——Arc 的安静来自这些，Arc 同时有品牌色和状态色。色彩承载的语义是功能，不是装饰：

| 用途 | 改前（正确） | 你改成了（错误） |
|---|---|---|
| 在线/成功状态（`--green` 亮色） | `#4c8967` | `#7a7a7a` |
| 在线/成功状态（`--green` 暗色） | `#8bb79a` | `#acacac` |
| 注意状态（`.dot.amber`） | `#b39051` | `#939393` |
| 表单错误（`.form-error`） | `#c5674e` | `#797979` |
| 被@的高亮（`.mention-tag` 亮色） | `color:#a05013; background:#be731418` | `#5d5d5d / #7c7c7c18` |
| 被@的高亮（`.mention-tag` 暗色） | `color:#edb879; background:#d1902820` | `#bfbfbf / #96969620` |
| 危险操作（`.danger-action`） | `#b34b47` | `#616161` |

用户看不到谁在线、分不出删除按钮、被@了不显眼、报错像普通说明文字。这是功能损伤，不是审美问题。

**要求**：按上表把功能色恢复原值。中性色（`--bg`、`--surface`、灰阶微调）不动，你调的那些可以保留。

## 你犯的错：替用户废弃了偏好

你在代码里强制 `placePresentation = "panel"` 并注释 "Ignore the obsolete modal preference"。不许替用户做废弃决定。正确做法：读到旧的 modal 偏好时做一次性迁移（视为 panel），没有偏好时才用默认 panel。注释删掉。
