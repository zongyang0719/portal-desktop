# 场景、导航与面板 · 2026-10-02

本次用户指令：场景只表示对话，功能不随场景改变；功能和场景可置顶；功能入口在展开侧栏的场景上方；两个面板操作等价，换边位于分隔线上，支持拖动。

## 当前实现

- 展开侧栏显示混合置顶、消息、功能、场景。消息和功能为两列带文字入口，可折叠分组；展开时移除独立竖栏，侧栏收起后显示图标入口。
- 置顶保存在本机，按 endpoint + being 隔离。功能和已置顶项通过右键或 Shift+F10 操作，场景沿用已有右键菜单；行内不显示图钉。重命名按 scene_id 跟随新标签。置顶只是快捷入口，不强制面板保持打开。
- 对话和功能各有同样的收起/展开控件；功能面板另有明确的关闭按钮，关闭后只剩对话。“浮动/停靠”在“更多操作”文字菜单中，不与收起混用。
- `motion-panels` 的 Group、Panel、Separator 和 Handle 承担分栏拖宽、折叠和拖拽换序。交换按钮在鼠标悬停分隔线时出现在中央。窄主区域沿用 600px 门槛切上下分屏。
- 换边、浮动不切换场景或功能。所有摆放只保存在连接级窗口状态中；切换场景不恢复任何场景布局。
- 点击已打开的功能只展开/定位，不切换开关或重复读取；新功能在已有功能栏中切换，对话始终独立。首次分屏为功能左、对话右；手动换位之后保持用户的顺序，导航不自动调换两栏。
- 收起的面板以带名称的窄条恢复；不让两栏同时消失。
- 侧栏顶部折叠按钮避开原 PR 的原生窗口拖动区域；展开态恢复 `--sidebar-material` 透明材质。显示名取 Town 的 `displayName`，仅在缺失时回退到路由 slug，不改对话路由。

## 存储与兼容

新键 beings:window-placements:v2 以 endpoint + being 存储布局与当前功能。首次使用从当时选中的旧场景迁移一次；旧 beings:scene-placements:v1 数据保留。导航置顶使用独立 beings:navigation-favorites:v1。

阅读位置作用域同步改为 endpoint + being，因此场景切换不清空阅读搜索、详情、滚动和资源回复；不同连接及 Town 身份仍隔离。对话本身的场景草稿和消息路由继续使用原有协议。

## motion-panels 参考与技术选择

使用 [motion-panels](https://github.com/letstri/motion-panels) 0.6.1 和 Motion 13.5.0 的真实 React 组件：Group、Panel、Separator、Handle。`Group` 的 `order` 与带稳定 key 的面板实际渲染顺序同步；拖动手柄时由 Motion 的 `onOrderChange` 换位，键盘方向键沿用 `Handle` 自带行为。分栏拖宽、折叠和换序动画也由库负责，不再用自定义松手阈值或禁用回位动画。任意位置浮窗并不是该库的能力，仍由已有坐标模型处理；浮动状态下两种面板均保持挂载。

浏览器为原生 WebContentsView，在面板隐藏、拖动、浮窗和尺寸变化时同步可见性及边界，避免覆盖已收起的 UI。

## 本轮范围与验收

目前仍是对话 + 一个独立功能面板，每个都能浮动；多个功能同时并排仍需拆分 Town 的单视图状态与数据模型。没有宣称已提供 N 个功能并排或跨原生窗口拖拽。demo/collaboration.html 复用真实 DesktopWorkspace 与 AppModel，只替换数据传输；它是可交互预览，不能代替真实 Electron 检查。

回归覆盖：当前场景旧布局迁移一次、保留旧数据、连接隔离、场景切换保持功能阅读、置顶持久化、手动收起后从导航恢复、草稿与引用。视觉仍待用户反馈，不称为最终验收。

## 原生鼠标命中复核

- 用户实际鼠标点击再次无法切换侧栏。前一轮只用辅助功能动作触发了按钮，因此将“可触发”误判为“鼠标可点击”。独立 rail 中的按钮和覆盖整个顶部的原生拖动区成为兄弟节点，拖动区会抢走原生鼠标命中；可见层级与浏览器预览不足以证明 Electron 命中正常。
- 参照 PR #3 的控制区边界，折叠时顶部拖动区从 `--scene-sidebar-controls-end` 开始；展开时顶部拖动区从侧栏右缘开始，侧栏自身的顶部拖动区只覆盖按钮右侧。rail 的实际宽度也覆盖按钮坐标，不再让按钮越出零宽或 52px 的父容器。修订包 `out/panels-motion-source-20261002-v3/` 已安装；真实客户端里鼠标点击展开成功，用户随后操作应用，未复核反向点击。
