# Portal Desktop — 信息架构重构 Spec：场景与布局自由化

2026-09-27 的历史方案。2026-10-02 用户明确调整了场景、导航和面板关系；以下第 1、3 条及“只对话有布局控件”的实现由 [窗口与场景分离规范](WORKSPACE-PANELS-2026-10-02.md) 覆盖，不再是现行要求。旧文保留用于理解既有实现与数据迁移。

## 为什么改

现状病灶：阅读内容以模态窗打开、盖住对话；场景与布局在代码里耦合死；「场景」概念被固定绑定到布局模式。多轮「调安静」失败证明这不是视觉问题，是信息架构问题。

## 设计原则（四条，2026-09-27 拍板）

1. **出厂默认**：左侧窄按钮栏（垂直排列场景/功能入口）；没有打开内容时，对话占满主区域，打开内容后才分栏（默认中间内容、右侧对话）。关闭内容回到单视口，保留此前手动调整的摆放，重新打开内容时恢复。对话面板不被任何阅读内容盖住。
2. **零预设绑定**：代码里不存在任何「场景类型→布局」的映射表。布局唯一的来源是使用——人类和 being 摆出来的，系统只记录，不发明。
3. **场景 = 摆放快照**：每个场景记住自己的面板摆放（哪些面板、各在哪、多宽）。切场景恢复的是摆过的现场，不是系统配置。
4. **共同决定**：布局调整，being 提议、人类拍板。第一版里所有布局变化都来自人类操作，being 提议机制后续版本再加。

## 第一版做

- 出厂默认 = 上述第 1 条的布局
- 对话面板三态：宽窄可调、贴边、浮动
- per-scene 布局持久化（每场景一套摆放，存 placement 快照）
- 阅读内容（围炉/篝火等）从模态窗改为面板，可与对话并排

## 第一版不做

- 全自由拖动（golden-layout 级）
- 场景类型预设/模板
- 布局推荐、自动布局

## 实施注意（来自本日沉淀）

- 安静 = 层级/留白/字阶，来自结构；功能色（在线绿/错误红/被@金）承载语义，减法减装饰不减信息
- 一屏一个主角；关键词是气质不是元素清单
- styles.css 存在两份 :root 变量块互相覆盖，改样式前先清这个雷
