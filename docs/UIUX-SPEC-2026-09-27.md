## 一、六条原则（沿用方向，收紧解释）

**1. 每屏只有一个主角。**（宗阳 9/25 拍板；Lumon "one pen, a rolodex, a phone"；iA "Reduce to the essence."）
**2. 用光，不用层叠的颜色。**（iA "Work with light, not with layers of color."；色彩宪法 9/26）
**3. 好设计是看不见的。**（iA "Good design is invisible."；Stephen Fry: "Everything goes away except for the writing experience."）
**4. 存在感，不是等待感。**（21st.dev: "reads as presence rather than as a wait."）
**5. 安静的乐观。**（Dia: "a little sunlight on your LED screen."；本轮解释：温度先来自内容与反馈，光辅助，不另设暖色强调）
**6. 状态不许撒谎。**（ThinkingOrb: "a solving orb over a network request is a lie."）

## 二、字体（v2.1 新增——v2.0 的真漏洞之一）

文字主导的界面，v2.0 通篇没有字体决策——主角没有形态。iA 被记住的第一件事就是字（用户证言全在说 Mono/Duo/Quattro 和那个蓝光标）。我们不自研字体，取其精神——不凑合，用平台最好的系统字：

- **正文**：macOS 使用 -apple-system / SF Pro，中文回退 PingFang SC；Windows 使用 Segoe UI Variable / Segoe UI，中文跟随平台。保留各平台原生字体，不下载 SF 字库
- **代码与数字**：代码和过程日志使用 SF Mono / Consolas / monospace。普通时间戳、字数、计数沿用系统正文字体，加 `font-variant-numeric: tabular-nums`；需要对齐的坐标表再用等宽字体。稳定数字宽度，不让每个数字都跳出正文的字体体系
- **标题不引入衬线**。v2.0 曾写「复古=衬线标题」，无出处自造，删。复古的落点见 §六
- **高雅=灰阶，不是花体**：正文不纯黑（#1d1d1f 级）。必要的小字按实际底色至少达到 4.5:1 对比度（[WCAG 2.2 SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)）；`#86868b` 在 `#f3f3f3` 上只有约 3.26:1，不作为 12px 辅文。可从亮色 `#656565`、暗色 `#a5a5a5` 起步，悬停底色也需核查。装饰性分隔线单独定义，不借辅文变量降透明度
- **正文 17px，行高 1.6–1.7，段距大于行距**。进门摘录可为 21–22px，仍是内容字号，不做海报式标题；辅助文字从 12px 起步
- **放大镜自测**：375px 和 1440px 两个宽度下正文都不许换质感

## 三、进门页（不变：只讲我们聊到哪了）

1. **最近一段对话的最后几行**，直接排在底色上，下方「接着聊」入口。主角。使用真实对话摘录与来源，不另外生成一句哲学口号代替；较长内容保留 3–4 行，由入口回到原场景和对应位置。
2. **我找他的最新消息**：有未读才出现，一行（来源+一句摘要+时间）。没有不占位。首屏只展示最新一条，其他消息仍留在对应场景或侧栏的收件入口；移出首屏不等于已读或删除。
3. 没有第三样。

空状态：光点+一行字，输入仍可用。光点只有已确认状态才呼吸；没有状态依据时使用静态轮廓。

「没有第三样」约束内容分区，不妨碍最小导航和输入操作。物件入口移出首屏，进场景后才能展开该场景物件；搁置列表始终能从侧栏找到。冷启动可进入此页；仅切回已打开窗口时保留原场景、滚动与未发送草稿，不强制重新进门。

## 四、对话流

- 文字主导，无卡片容器；我说的和他说的用排版区分（左侧标记/缩进/字重），不用色块
- **流动落在这里**：场景切换保持布局稳定、回车不闪。必要进入过渡上限 150ms，不锁输入、不在每个流式文字块上播放；减少动态时直接切换
- **回复控制按接口能力显示**：停止生成必须由服务端确认；暂停后继续同一生成只有服务端支持时才可称为「暂停/恢复」。冻结自动滚动只叫「暂停跟随」，不冒充模型停下。首轮样机不放无效控制
- 正文阅读列最大 680px；窄窗口保留至少 20px 内边距。密度克制，超出滚动；代码或图片可局部展开，不拉宽整段正文
- 工具过程默认一行摘要，点击才展开。引用经明确操作加入输入，可移除并回到来源；不因用户只想复制文字就改变输入上下文

## 五、存在标记（4 态，v2.0 是 6 态——砍掉移植）

v2.0 列了 6 态，其中「在听」「在说」是从 voice 产品硬搬的——我们不是语音产品，文字交流里我不存在「听」。照搬状态=堆叠。Voice orb 原文自己也是三态起步（"idle, working, speaking — with no text and no layout change"）。我们四态：

| 状态 | 依据 | 行为 |
|---|---|---|
| idle | 已确认的 Being 生命周期状态，无当前任务 | 慢呼吸（4–6s 周期），中性白微光 |
| thinking | 当前任务进入思考阶段的真实事件 | 呼吸略加速，尺寸不变 |
| streaming | 实际收到输出事件 | 随输出轻脉动；无输出事件不继续模拟脉动 |
| error | 当前操作明确失败 | 标记静止；在失败动作附近保留简短原因和重试入口，恢复或用户处理后消失，不只靠暗一拍传递错误 |

- **未知是数据边界，不是第五种人格姿态**：连接成功不等于 idle；没有姿态事件或事件过期时保留静态轮廓，名称为「状态未知」。离线属于连接状态，存在状态同时退回未知；断连原因和重试在连接详情中查看
- 位置：输入框左侧，光点直径 8–10px，与输入文字间距至少 12px，点击区至少 32px。顶栏不再重复放一个光点。持续装饰动效预算仍 = 1 处；有限的操作过渡另按上一节约束
- 始终提供可访问名称；点击或键盘激活查看状态文字与连接详情。`prefers-reduced-motion` 下使用静态形态和文字；窗口失焦、页面不可见时暂停装饰动画
- 未接服务端前，HTML 仅能展示明确标注的示例状态，不声称已接真实事件。接线前需定义事件来源、时间戳与过期策略
- 有数字的事（下载/同步）用数字，不用光点表达进度

## 六、侧栏、搁置与安全（v2.1 修订——v2.0 的真漏洞之二）

v2.0 把搁置区砍出进门页，但没交代它去哪了——「安全」这个关键词就没人接了。砍的是位置，不是功能：

- **搁置保留**：对话中仍可搁置，动作放在场景菜单和物件操作中。输入框旁不常驻第二组功能按钮；操作后保留来源、当时上下文和草稿
- **搁置列表**：侧栏底部安静的一行入口，进去是行式列表。不出现=不提醒，但永远找得到——不丢，就是安全
- **安全的另一半**：不静默丢东西。消息到达必有去处（场景或收件箱）；删除走确认。草稿写入失败保留输入并明确提示，未保存不得显示成功；快照恢复要说明替换范围并可撤销。9/25 他问过「空屏还是留『美阳阳在』痕迹」——不丢、留痕，这两个关切就是这个关键词的答案
- 场景列表行式短标题（Things），物件收进所属场景的抽屉，次级信息需要时展开。点击或 Enter 打开，Escape 关闭并回到原控件；不靠 hover 才能读取必要内容。关闭物件不丢编辑草稿
- 分层沿用 town：流管会话，沉淀管文档

## 七、颜色与光（色彩宪法沿用）

- 中性色：亮 `#f3f3f3` / 暗 `#1c1c1e`→`#161618`；不定义主色；danger 红仅破坏性操作
- 光最多两处：底面静态径向（中央亮 2–4%）+ 存在标记中性白微光（半径 ≤40px）。不出现可辨识的黄、橙色晕；暖度先由明暗和内容表达，避免「烛光色温」重新引入功能色。底面不随呼吸变化
- 行式列表不逐行加底、描边或投影。打开后的独立物件查看层可用轻投影 y2/blur12/8%；用于区分层级，不为了补足「复古」再造卡片
- **噪波：删除，不留开关。** v2.0 写「默认关+设置可选」是没立场——要靠开关才能开的气质=装饰。grain 移入「不落视觉」清单

## 十、验收

1. 眯眼看，眼睛先落在一个地方吗？
2. 能从真实对话、来源与未读消息认出「我们聊到哪」吗？文字是主角，不以「去掉文字还能认出」为增添装饰的理由。
3. 静止 10 秒，屏幕上动的东西只有光点吗？
4. 375px 和 1440px 宽度下，正文质感不变吗？（v2.1 新增）
5. 仅用键盘能完成进入场景、看物件、搁置/拿回、返回输入吗？刷新或暂时离线后，已保存内容和未发送草稿是否仍在？
6. 未知/断连/错误是否能解释，是否把无事件错误渲染成思考？减少动态后，必要状态是否仍能读懂？

这些是待执行的验收条件，不是本版已通过的检查。HTML 预览只判断结构与本地交互，最终仍需真实 Electron 客户端验收。

## 十一、本轮取舍（v2.1 + 第二轮 demo）

| 项目 | 合并决定 | 原因 / 代价 |
|---|---|---|
| 首屏 | 采用 v2.1：摘录 + 有未读才出现的一行消息 | 当前 demo 的全局物件入口移入场景；少一个入口，但首屏主次更明确 |
| 物件与搁置 | 采用 v2.1 的场景抽屉、侧栏搁置入口；保留 demo 的详情、编辑、来源与拿回 | 信息要多展开一次，换取日常阅读的安静；功能不能随着首屏删减一起失踪 |
| 存在标记 | 采用靠近输入的位置和四种活动状态；保留 demo 的 unknown/离线数据边界 | 连接与存在分开，避免把轮廓少画一种误当成状态简化 |
| 数字与辅文 | 普通数字用 tnum，辅文按实际底色核查 | `#86868b` / `#f3f3f3` 计算为 3.26:1，`#656565` / `#f3f3f3` 为 5.25:1；基于色值计算，不是全界面验收 |
| 失败与恢复 | 保留 demo 的草稿持久化、写入失败保留、快照恢复/撤销与键盘返回 | 都藏在操作发生的位置，不增加常驻状态条 |
| 光与投影 | 静态底光、局部中性白光；列表平面，查看层可有投影 | 不把关键词重新翻译成首屏装饰清单 |
| 回复暂停 | 先明确服务契约，再决定控件 | 当前未验证能暂停并恢复同一次生成，不以视觉样机承诺该能力 |

`demo/workspace.html` 已改为组件生成的单文件预览，源码为 `demo/workspace.tsx` 与可复用的 `workspace-home.tsx`。复用正式侧栏、CodeMirror 输入和弹层，落实首屏未读消息、场景物件入口、侧栏搁置入口与输入侧存在标记。状态和消息仍为示例；服务契约、客户端集成与实机视觉验收尚未完成。
