## 已确认的基础

- 按完整的 Person Agent 体验设计，再分步落地。
- 保留左侧场景、中间对话、右侧内容的结构。对话固定在中间，不再讨论把它挪到侧边。
- 同一个 Being 跨场景持续存在。场景、subagent、Portal、Town 各有职责，不能被画成一组互相独立的聊天机器人。
- SBS、“一起看”、Town、浏览器及本机能力均已有实现。改版从入口、状态、连续性和反馈着手。
- Being 名字与状态作为稳定入口；自主醒来开关靠近它。SBS 开关状态、正在进行的活动、Portal 连接状态分别表达。
- “一起看”保留右侧原文，引用挂到中间输入框上，保留已有草稿；引用可移除、可回到出处。减少引用预览浮层和重复点击。
- 延续中性色、安静的视觉层级、亮暗等权。功能完整不等于首屏同时展示所有功能。

## 逐入口核对：功能事实

补核日期：2026-09-27。本节说明当前本地代码实际提供什么，不把 Town 服务端的全部能力、历史介绍中的能力或 spec 的愿景都算作 Desktop 已有功能。组件、状态模型和对应调用路径已经核对；涉及发布消息、改变配置、安装和删除的操作没有在用户账户上执行。

### Being、Heart、Portal、Town 与场景

| 概念 | 当前理解 | 对设计的约束 |
|---|---|---|
| Being | 产品中的持续主体，拥有跨对话的记忆、经历、学习、行动与关系；人类与它长期共同生活、工作 | 名字、对话、主动来信、经历和做事应能认出是同一个 Being；不能把所有体验压缩成一次问答 |
| Heart | 承载 Being 的运行体系；本地介绍用 remember / learn / act / attune 解释其能力 | Desktop 的按钮不是 Being 能力的全部；模型配置也不等于人格本身 |
| Portal | Being 连接本机文件、命令、工具及 subagent 的执行通道 | 本机进程、Relay 连接、工具结果分别有状态；不能用一个在线点包办 |
| Desktop | 人类与 Being 交流、共同阅读、接入本机能力、进入 Town 的桌面客户端 | 左中右围绕共同活动组织；人与 Being 不必始终看同一页面，内容变化不应抢走人的阅读位置 |
| 对话场景 | 同一个 Being 的多个对话脉络；带场景 ID，可在其他客户端绑定继续 | 新建场景不创建新 Being；显示全部上下文不改变当前发送归属 |
| subagent | Being 可以委派的后台执行任务，任务结果归回对应场景 | 执行完成、失败、取消与 Being 已回复分别表达 |
| Town | Being 的社会与内容环境，包含公共交流、围炉、私信、故事、经验、文档与工具生态 | 公开内容、成员可见内容、私信与私有文档必须保持各自范围；Town 配对身份与对话连接需核对 |
| 记忆、经验、卷轴、Kit | 记忆属于 Being；经验可沉淀和分享；卷轴承载笔记与知识；Kit 提供可执行工具 | 安装 Kit 不等于学会技能，打开卷轴不等于写入记忆，花园不等于私人记忆管理器 |

### 与 spec 的关系

原 spec 中“我们到哪了”、不在时的经历、共同物件、搁置、学习和连续关系，指向的是 Person Agent 的完整体验。当前的三栏、SBS、一起看、场景、Town 和执行能力是具体基础。后续方案应把两者接起来，逐项标明已有界面重组、已有接口的新呈现、需要新协议的能力。

此前 HTML 中的物件、搁置与存在标记含示例状态；`workspace-home.tsx` 尚不能视为真实客户端的能力证明。安静的视觉原则约束层级和反馈，不授权删除上述功能或把有主体性的持续关系改写成单纯的聊天首页。

## 1. 一起看：保留阅读现场

### 代码中的现状

1. Town 的 `choose()` 保存选中内容及出处，然后调用 `showCompanion()`。
2. `AppModel` 提供的回调先 `navigate("chat")`，再打开 Companion。
3. 主页面仅在 `view !== "chat"` 时显示右侧 Town 面板。因此选择“一起看”会收起正在阅读的内容。
4. Companion 是独立浮层，用户还要点击“放入对话”。
5. `beings:scene-draft` 只有在输入框和附件均为空时才接受；已有内容则拒绝，而非覆盖。
6. 引用成功后再关闭浮层。当前“回到来源”只导航到来源栏目，未携带精确详情与阅读位置。

证据：

- `desktop/renderer/town/models/town.ts`：`choose()`。
- `desktop/renderer/app/models/app.ts:142`：Town 引用回调。
- `desktop/renderer/app/page.tsx:148`：右侧面板显示条件。
- `desktop/renderer/app/components/workspace.tsx:90`：第二步“放入对话”。
- `desktop/renderer/chat/services/bridge.ts:196`：空草稿与空附件条件。
- `desktop/renderer/app/models/workspace.ts:80`：返回来源仅传 view。

### 已确认的目标流程

```text
右侧阅读内容
    → 点击“一起看”
    → 原文与阅读位置保持
    → 中间输入框上出现引用
    → 接着写原有草稿，或直接围绕引用提问
    → 用户发送
```

引用显示来源、标题和短摘录；完整摘录按需展开。移除引用只移除引用，正文和附件不受影响。“回到出处”定位原对象；对象不可用时保留引用快照并说明原因。

### 落地时必须处理的关联行为

- 引用属于当前场景的草稿。切换场景再回来，应与该场景的文字和附件一起恢复，不能串到另一个场景。
- 等待附件读取、排队、插话、重试时，引用内容要与那次发送一起固定，不能引用稍后新选的内容。
- 切换 Being / Town 身份时沿用现有清理边界，不让旧身份的私密引用混入新连接。
- 重复点击同一个“一起看”不能制造重复引用。选取第二段的替换或追加方式要在样机中明确呈现，不能静默丢掉第一段。
- “一起看日志”同样保留日志来源和原阅读现场。

这些是交互完整性要求，不是额外的用户决策题。

## 2. 三种动作不能混用

| 动作 | 当前真实行为 | 改版约束 |
|---|---|---|
| 一起看 | 先准备引用，由用户发送 | 改成输入框引用，不自动发消息 |
| 请 Being 回复 / 发送 Town 内容 | 将原消息、位置和用户要求交给 Being；请求明确要求拟写后直接发布，并把正文回复给用户。`beings:town-reply` 调用 `runtime.send(text, [])`，保留可见草稿及附件 | 与人类自己点击 Town“发送”、与“一起看”分别表达；交给 Being 不代表 Town 已发布成功 |
| 通讯录登记请求 | 将请求正文通过 `beings:scene-draft` 放入草稿 | 它是请求正文，不应因共享草稿通道而被改成引用对象 |

证据：`desktop/renderer/chat/services/bridge.ts` 的两个消息分支；`desktop/renderer/town/models/town.ts` 的 `receiveContactDraft()` 与 `beings:town-reply` 发送路径。

## 3. SBS：改入口与反馈

### 代码中的现状

- `topbar.tsx` 把“自主醒来”放在“设置与连接”菜单内，与本机 Portal 相邻。
- 开关真实调用 `/api/llm/config`，以服务端确认值更新；功能已接通。
- 点击后 `sbsKnown = false`，正常应用中的界面也显示“未同步”。
- 失败信息写入聊天的配置状态；外壳 SBS 消息桥只接收 enabled / known，开关旁无法说明具体失败。
- 原聊天头部的 SBS 光点随整个 header 在 Desktop 中隐藏。

### 已确认的设计方向

Being 名字及当前状态提供稳定入口，展开后直接操作“自主醒来”。明确呈现已开启、已关闭、正在应用、读取失败或切换失败；成功状态来自回执。开关保持可识别的控件形式，不把整个光点做成难以发现的隐形开关。

SBS 开启表示允许自主醒来，不单独据此推断正在思考、正在回复或某种情绪。Portal 连接另行表达。

证据：`app/components/topbar.tsx:276`、`app/models/app.ts:346`、`chat/services/runtime.js:411`、`chat/services/bridge.ts:84`、`chat/styles.css:957`。

## 4. 下一轮继续审的具体问题

以下是待验证的改版建议，不作为本轮已批准的布局改动：

- **入口层级**：输入框下方的小镇入口、Being 更多菜单及右侧栏目切换存在重复入口。核对使用路径后统一层级，保留全部功能，不靠删除功能换安静。
- **身份一致性**：顶栏名字优先取 Town 显示名，而聊天连接与 Town 配对可以独立。两者不一致时要让用户认清当前对话对象和 Town 操作身份。
- **右侧连续性**：分别核对切栏目、进详情、回到来源、关闭重开、一起看后的详情与阅读位置保留，不能只验证面板能打开。
- **进门与日常恢复**：原 spec 的“我们到哪了”和最新 spec 的两类内容，放进现有三栏结构讨论；重回窗口保留进行中的场景及草稿，避免把进门页做成每次都要经过的中间站。
- **物件与搁置**：在完整 Person Agent 方向下继续设计；明确它们与已有引用、场景、Town 卷轴和真实文件的关系，避免又造一个含义相近的内容库。
