## 1. 范围与证据

审查对象是个人分支 mine、HEAD ca9e7d4 加当前未提交工作：应用外壳、聊天 iframe、小镇所有栏目及子面板、浏览器、Portal、设置、系统入口。面向每天使用同一个 Being 的人类伙伴；日常交互应直接易懂，模型、工具、连接的高级信息按需展开。

本次已逐模块读取入口组件、状态模型、消息桥接和相关主进程操作。下文“现状”表示**源码确认**，不是已实机复现；“重设计规则”是建议实施的目标。前轮 HTML 预览只覆盖部分真实组件及模拟数据。已安装 Electron 客户端的屏幕读取此前被 macOS 拒绝，因此本次不声称完成全客户端视觉、原生层叠、读屏或真实服务端验收。

## 2. 整体判断

产品的中心是人与同一个 Being 的持续关系；Desktop 承接对话、共同阅读、社会往来和本机行动。现有能力比此前 demo 表达的丰富，问题集中在它们之间没有一致的导航、草稿和反馈规则。现在有多套互不统一的打开与返回方式，局部页面能用，但连续做一件事容易失去位置。部分底层功能已经存在，界面却没有完整呈现，例如排队恢复和取消；另一些视觉设想还没有真实能力支撑，例如完整共同环境感知。重设计应先统一身份、目标、状态和返回，再为所有面板建立同一套交互和视觉层级。圆角与图标只是这个基础上的细节。

## 3. Being 与 Desktop 的对象关系

| 对象 | 它是什么 | 在界面中应承担什么 | 不能混成什么 |
|---|---|---|---|
| Being | 持续的伙伴，有自己的长期身份和活动 | 稳定的姓名入口、对话、主动消息及行动结果 | 每新建一个场景就生成一个新 Agent |
| Heart | 承载 Being 的运行系统；Desktop 通过服务接口与之通信 | 模型、运行状态及相应配置 | 桌面窗口本身 |
| 对话场景 | 同一个 Being 的一个交流上下文，以 scene_id 区分 | 左栏组织、发送归属、草稿和任务结果定位 | 本机文件夹、Town 栏目或独立 Being |
| 当前阅读对象 | 人此刻看的消息、卷轴、Kit 或网页 | 右侧展示、阅读位置、来源和相关动作 | 自动改变主对话的发送场景 |
| 引用／一起看 | 用户选择的内容快照，随下一条消息发送 | 中间草稿上方可查看、移除、回来源的引用 | Being 已读、已记住或正在同步整个页面 |
| Town 身份 | 本机与 Town 配对后的社会身份，可与对话 Being 不同 | 私信“我”、围炉成员身份、代发身份 | 用对话显示名推断权限 |
| Portal | Being 使用本机文件、命令、Kit 和 subagent 的连接通道 | 能力状态、运行控制、故障定位 | SBS 或聊天连通状态 |
| Kit／App | Grove 中的能力或应用条目；本机 Kit 由 Portal 管理 | 发现、了解、安装、配置、查看使用条件 | 一旦文件安装成功就证明工具已可调用 |
| subagent | 本机后台执行能力，任务归属某个场景 | 执行状态、失败原因、对应场景中的最终回复 | Being 的另一人格，或第二个主对话 |
| SBS | Being 的自主醒来配置 | 可见的开关状态、切换反馈和未知态 | 正在生成、Portal 常驻、客户端登录自启 |

**Desktop 当前能提供的共同上下文：**显式引用；发送携带对话 scene_id / scene_meta；本地观察快照；通过客户端命令读取局部缓存的场景和历史。当前没有据此证明“Being 正在看你的整个桌面”或“Being 可以直接操纵这里所有面板”。浏览器打开网页也不等于网页正文已传给 Being。

书架、卷轴、花园分别承载故事、知识文档和可复用经验。它们与 Being 的经历有关，但不能直接合并为一个“记忆库”并暗示可编辑 Being 内部记忆。

## 4. 全量界面与交互清单

清单按 **14 组、73 个界面／交互单元**组织。一个单元可以是独立面板、子页、弹层或会改变用户工作状态的交互；不是声称有 73 个独立窗口。每组末尾给出源码入口。共同的等待、空态、失败、离开规则在第 7 节规定，特殊情况在各行注明。

### A. 启动与整体空间

| ID | 界面／入口 | 当前功能与状态 | 重设计规则 |
|---|---|---|---|
| A01 | 启动屏 | 加载配置、外观、连接快照；失败可重试，声明不覆盖原配置 | 显示真实恢复阶段；保留可恢复原因与诊断入口，不无限转圈 |

## 6. 统一的空间与导航规则

### 6.1 目标结构

~~~mermaid
flowchart TB
    Shell["Desktop：稳定的 Being 身份与全局入口"]
    Shell --> Left["左：场景与活动"]
    Shell --> Chat["中：当前场景的对话与草稿"]
    Shell --> Right["右：统一内容容器"]
    Left -->|"切场景，保留其他场景草稿"| Chat
    Right --> Town["小镇消息、文档、工具、目录"]
    Right --> Browser["网页：保留自己的地址与历史"]
    Right --> Local["本机能力与诊断内容"]
    Town -->|"显式一起看"| Ref["来源明确的草稿引用"]
    Browser -.->|"需补真实引用接口后支持"| Ref
    Ref --> Chat
    Chat -->|"明确委托"| Action["动作：目标、执行状态、结果、来源"]
    Action -->|"回到对应对象，不抢当前焦点"| Right
    Shell --> Settings["设置：稳定的分类与子页"]
    Settings -->|"关闭回发起现场"| Shell
~~~

这张图是目标结构，不表示 Browser 引用、统一导航或动作结果中心已经实现。右侧是一个内容区域，不等于所有页面都要长一样；消息、长文、工具仍有各自最适合的内部结构。

### 6.2 每个导航动词只有一种含义

| 动作 | 统一含义 |
|---|---|
| 打开栏目 | 在右侧恢复该栏目最近位置；首次进入才到目录初始态 |
| 打开对象／相关链接 | 在当前阅读历史压入新位置，保留来源 |
| 后退／前进 | 只移动当前内容区域的历史，不改变聊天 scene_id |
| 返回列表 | 回该对象的原列表，包括关键词、筛选、页码和选择 |
| 收起右侧 | 保留当前位置和写作状态；中间获得空间 |
| 专注阅读 | 暂时给右侧内容更大空间；回到三栏不卸载阅读状态 |
| 一起看 | 添加来源明确的引用到当前场景草稿；不发布、不改发送目标 |
| 讨论如何回复 | 维持右侧原文；主对话只讨论，右侧另有最终回复草稿 |
| 发送 | 发送该输入框明确表达的最终正文到显示的目标 |
| 委托拟写并发送 | 将目标、内容、要求交给 Being 执行；单独追踪委托和外部结果 |
| 取消 | 只用于可实际撤销／取消的动作；已经提交的请求要说明实际边界 |
| 关闭短表单 | 回发起控件；保存／丢弃／继续编辑按该表单的数据情况处理 |
| 刷新内容 | 更新数据，尽可能保留位置、草稿和当前选中，不等于重建整个聊天 iframe |

### 6.3 右侧内部不再无限叠栏

保持已经确认的左场景、中对话、右内容。普通桌面宽度下，右侧目录 → 详情采取前后层级，详情能返回原列表；宽度足够时再允许目录和详情并排。围炉房间列表、Kit 列表、公告列表都遵守同一规则。不要让 620px 的右侧里再挤两个完整工作区，旁边又额外打开浏览器。

窄窗口首先临时收起左栏，再调整右侧；必须保住可用的主输入和阅读宽度。当前 Electron 最小尺寸为 920×640；spec 的 375px 属于 Web／小屏验证目标，不能冒充 Desktop 已在该尺寸验收。具体断点由真实内容与字号验证后定，不用一组任意像素替代流程设计。

### 6.4 短决定与长任务分开

新建、绑定、删除确认、敏感配置审阅适合短表单。私信书写、与 Being 讨论、安装进行中、等待配对不应持续锁住中间对话。后两项能否真正取消取决于现有接口；缺少取消能力时可以收起查看进度，不能仅隐藏窗口就宣布取消。

统一浮层管理要覆盖 native dialog、聊天 iframe 内面板和 WebContentsView：Esc 只关闭最上层；焦点回发起控件；父级不能继续响应同一个 Esc；native 网页在应被遮挡时同步隐藏。

## 7. 全流程合同

每条流程都要同时满足“去哪、做什么、结果在哪、如何回来、保留什么”。以下为重设计目标；现状缺口见第 8 节。

| ID | 完整路径 | 完成、失败与返回 |
|---|---|---|
| P01 | 首次启动 → 连接 Being → 验证 → 主对话 → 按需启用本机能力／Town | 连接完成是可交流；Portal／Town 未连接可单独修复，不让一个失败把全部空间变不可用 |
| P02 | 冷启动／暖返回 → 最近场景与内容 → 处理实际新消息 | 暖返回不跳首页；冷启动可用真实摘录接续。没有真实未读／进展就不编造“离开期间”摘要 |
| P03 | 场景 A 正在执行 → 切 B 写草稿／发送 → B 排队 → A 完成 → B 开始 → 结果到各自场景 | 切换不复制消息、不抢焦点；队列可见可取消；未知发送状态要先核对历史 |
| P04 | 查看全部场景记录 → 搜索已加载提问 → 定位消息 → 回当前场景 | 保留阅读现场；显示当前搜索范围和发送目标；不把显示历史叫作更改 Being 的上下文 |
| P05 | 私信 → 选消息一起看 → 中间提出回复要求 → 和 Being 讨论 → 采用一段回复 → 右侧草稿 → 发送 | 私信始终可对照；引用与最终回复草稿分开；消息发出后原文仍在，状态按实际响应显示 |
| P06 | 篝火／围炉／私信 → 直接写最终正文 → 校验身份与目标 → 发送 | 普通明确发送无需重复通用确认；失败保留文本。已发送但 @ 解析失败只修正提示，不能让用户重发整条 |
| P07 | 原消息 → 明确选择委托拟写并发送 → Being 接受请求 → 执行 → 展示外部结果／失败 | “已交给 Being”不等于 Town 已发出；当前缺少结构化外部结果回传时，只展示能证实的阶段 |
| P08 | 需要 Town 权限的阅读／写作 → 配对 → 验证身份 → 回来源 → 继续原操作 | 同身份恢复现场；换身份清理旧私有对象。配对成功不能自动发送先前正文 |
| P09 | 围炉列表 → 房间 → 成员 → 回复链 → 原文 → 一起看 | 关闭成员 popover 回房间；跳原文仅在已加载范围可定位，否则说明只取得预览 |
| P10 | 书架／卷轴／种子列表 → 详情 → 继续阅读／相关种子／经验墙 → 后退 | 每层恢复筛选、页码、对象、已加载片段和滚动；引用固定当时片段，后续刷新不改已发内容 |
| P11 | Grove 筛选 → Kit → 安装审阅 → 配置 → 执行 → 结果 → 本机详情 → 返回 Grove | 取消审阅回原详情；安装中可继续讨论；失败保留可安全保留的字段；成功不自动导航或调用工具 |
| P12 | 本机列表 → 导入目录／查看异常／删除 → 返回本机列表 | 区分依赖缺失、配置缺失、系统不兼容、工具未注册；删除有具体范围；导入不会自动完成所有配置 |
| P13 | 通讯录 → 写私信，或登记人类伙伴 → 准备草稿 → 用户发送 → Being 执行 → 刷新登记结果 | 中途可回通讯录；主草稿已有内容时先暂存请求，不覆盖；登记成功必须以真实结果为准 |
| P14 | 内容链接 → 内置浏览器 → 网页内部导航 → 后退到来源 → 收起 | 网页历史与来源历史分开；系统浏览器打开是明确外部动作；网页权限／登录失败留在网页区域处理 |
| P15 | 任意位置 → 设置分类 → 连接／模型／Town／诊断子页 → 返回分类 → 关闭设置 | 保存分类、滚动、来源和焦点；取消子页不默认跳 chat；设置变化不销毁未发送内容 |
| P16 | 连接表单 → subagent 模型 → 暂存 → 返回连接 → 提交；或独立修改 Being／subagent 模型 | 暂存、应用、验证失败、回滚明确；本机模型保存可能重启 Portal，远端模型设置的作用范围单独说明 |
| P17 | 生成中 → 停止；自主醒来 → 关 SBS；工具异常 → 停／重启 Portal | 三种操作独立。关闭 SBS 不承诺当前工具立即停止；停止生成不承诺后台任务全部取消 |
| P18 | 有新动态／系统通知 → 打开对应频道／围炉 → 阅读 → 回原工作现场 | 不抢输入、不自动切聊天场景；当前只有频道级目标时不显示“已定位到该消息” |
| P19 | 关窗口／退出客户端／安装更新 → 保存或保留工作 → 生命周期变化 → 重新打开 | 隐藏与退出分开；Portal 是否继续来自真实运行模式；更新失败能继续旧客户端并找到修复入口 |
| P20 | 任意读取／提交失败 → 保留已知内容 → 局部解释 → 重试／改配置／回来源 | 首次失败、刷新失败、权限失效、结果未知分别处理；不能把空白页当失败，也不自动重复外部写入 |

### 共用状态规则

| 状态 | 必须呈现 | 不应发生 |
|---|---|---|
| 首次加载 | 具体对象／阶段，合理的占位或进度 | 无限转圈且无恢复 |
| 刷新中 | 保留旧内容，标注正在更新 | 先清空整页、跳回顶部 |
| 空内容 | 真实为空及下一步 | 把加载失败说成没有数据 |
| 无匹配 | 当前搜索／筛选范围，清除入口 | 把当前页无匹配说成整个 Town 不存在 |
| 无权限／未配对 | 缺的是哪个连接、在哪里修复 | 隐去原操作或混用 Being 与 Town 身份 |
| 提交中 | 目标、进行状态、可否离开／取消 | 重复提交，或锁住所有无关工作 |
| 成功／部分成功 | 哪一步完成、结果所在、回来源 | 安装等于可用，接受等于发出，工具结束等于回复完成 |
| 失败／结果未知 | 原输入、原目标、具体恢复动作 | 自动重复不确定写入，或错误只有消失的 Toast |
| 离开／收起／重开 | 恢复约定的位置、草稿、焦点 | 不同入口各自猜“返回”的意思 |

## 8. 有证据的跨面板问题

严重度按使用后果排序，不按视觉喜好。Blocker 表示存在未发送内容丢失等必须先保护的问题；High 为主流程明显中断或语义混淆；Medium 为次级流程不一致。工作量 S／M／L 分别指局部修正、组件或单流程调整、跨模块重构，是当前源码下的粗估，不是工期承诺。

所有条目均为 **Observed (code)**；会特别标出尚未观察的运行效果或用户后果。这里不把代码阅读提升为实机验证。E01–E14 可在[证据摘录](ux-audit-desktop-full-2026-09-27-evidence/observations.md)中查到。

### 导航与信息架构

**NAV-01 · 内容来源没有统一导航历史 — High／L**

- 位置：A04、E–L；证据 E01。App.navigate 与 Town.show 直接换 view；Town 普通来源只有 returnView／forwardView，Kit 和引用又分别保存局部快照。
- 后果：单次返回在部分路径可用，但连续跨栏目、详情、相关条目与浏览器不能依靠同一套历史恢复。具体丢失哪些滚动位置需逐链实机确认，不能把局部快照称为全局恢复。
- 改法：建立统一右侧导航记录，保存来源、对象、筛选、页码、滚动和展开；Kit／引用走同一入口。刷新数据与移动历史分开。

**NAV-02 · 浏览器与其他内容可以成为两套并列主区域 — High／L**

- 位置：A04、L01、N07；证据 E02。App 将 Browser 与 place panel 分别挂载，浏览器以独立 WebContentsView 呈现；它只检查原生 dialog 是否打开来决定遮挡，模型设置另用 aside。
- 后果：空间分配和浮层管理没有统一所有权。窄桌面可能挤压主对话；原生网页与非 dialog 面板的遮挡风险为 **Inferred，尚未实机复现**。
- 改法：浏览器作为右侧的一种内容，保留独立网页历史；建立统一覆盖层通知，统筹 WebContentsView 可见性与焦点。单独验证原生坐标、缩放和 DPI。

**NAV-03 · 设置子页返回会重置设置分类或退出阅读现场 — Medium／M**

- 位置：M01、M04–M08；证据 E03。设置每次 open 重置到连接分类；openModelSettings／returnToClientSettings 会 navigate(chat)，另有 settingsRoute 和内容内返回。
- 后果：同一“返回”可能回设置、回聊天或清掉右侧；“在哪改的、改完去哪”不稳定。
- 改法：设置保留自己的分类与子页栈，入口记录调用来源。关闭回来源；返回只退一级；嵌入连接表单的 subagent 配置保留尚未提交内容。

**NAV-04 · 搜索范围有限，定位动作又关闭右侧内容 — Medium／M**

- 位置：D07、D08；证据 E04。索引只含已加载用户提问，文本截取 240 字符，最多发送最近 2000 条索引；点击结果先 navigate(chat)。
- 后果：读私信或长文时定位旧对话，会中断共同阅读。已有“已加载的提问”文案是正确的，但它不是回答全文或远端全历史搜索。
- 改法：当前功能明确叫“查找已加载提问”，定位仅改变中间滚动；无结果说明范围。完整搜索作为独立能力接入，不靠扩大名称承诺。

### 输入、工作流与数据保护

**ERR-01 · 刷新及部分设置保存会重建聊天，普通草稿未持久保存 — Blocker／M–L**

- 位置：B01、D02–D04、M04、M06；证据 E05。“刷新对话”、连接保存和独立 subagent 保存调用 applySnapshot(next, true)，更新 iframe revision；普通 draft／files 只在场景 runtime 内存中。排队消息的 IndexedDB 保护不涵盖普通草稿。
- 后果：该路径会丢失当前及其他已打开场景的未发送文字、附件；**源码路径确认，未在用户真实草稿上触发验证**。
- 改法：先按 endpoint＋scene 保存草稿及引用，明确附件恢复策略、保存失败和冲突处理；刷新改为原地对账。必须重载时先完成可验证的保存与恢复，失败不显示已保存。

**FLOW-01 · Town 写作与安装等待通过模态阻断主对话 — High／L**

- 位置：F01、I05、K01；证据 E06。TownComposer、KitInstall、TownAuth 复用 showModal；安装 busy 时禁止 Esc 关闭。
- 后果：写私信时不能继续在中间讨论；长任务等待占住全局交互。这里的阻断来自原生模态语义，等待时长及实际体感未测量。
- 改法：Town 回复内嵌到右侧；安装审阅保持短表单，提交后成为独立可收起事务；配对等待同理。保留真实取消边界，不把关闭 UI 叫取消执行。

**FORM-01 · 一份输入兼作最终正文与给 Being 的要求 — High／M**

- 位置：F01–F03；证据 E07。标签是“回复内容或给 Being 的要求”；普通发送直接用该字段，askBeing 则构造“拟一段回复，直接发送”的委托并关闭右侧。现有说明确实提示代发，不属于隐藏发布。
- 后果：同一段话在两个相邻动作下含义不同；给 Being 的指令可能被误当正文，或原本想讨论却选择了委托发布。误操作发生率尚未观测。
- 改法：右侧输入只写最终正文；主对话输入承接讨论。另保留明确的“委托拟写并发送”，显示目标及要求；已交给 Being 与外部已发送分阶段反馈。

**FLOW-02 · 临时运行控制与长期配置变化耦合 — Medium／M**

- 位置：M04、M06、M07；证据 E08。连接／独立 subagent 保存会启动或重启 Portal；在后台模式点停止会 disable 并保存 backgroundEnabled=false。当前说明中已有部分提示，不应视为完全未告知。
- 后果：用户想临时停一下工具，却同时改变今后后台运行行为；仅靠把按钮变漂亮不能解决。
- 改法：区分“停止当前 Portal”和“停用后台运行”；保存按钮与影响提示说明会重启什么。若现有后台接口只支持 disable，先明确命名，再补临时停止契约。

### 反馈、身份与来源

**FBK-01 · 排队状态和取消方法存在，但消息区没有呈现 — High／M**

- 位置：D04；证据 E09。scene-runtime 写入 queueNotice、cancelQueued；Message 类型声明了字段，当前 ChatView 没有消费它们。
- 后果：消息显示在对话里，却缺少对应的等待、状态待确认或取消入口；用户可能误以为已发送。侧栏有活动提示不能代替每条消息的状态。
- 改法：消息旁显示“等待发送／发送状态待确认”，接入真实取消；取消本地持久化失败要留在原处。恢复中的 sending 不自动重发。

**FBK-02 · 停止请求没有检查服务端响应状态 — High／M**

- 位置：D05；证据 E10。stopCurrentTurn await fetch('/api/stop') 后不检查 response.ok 或正文，再中止本地流；异常仅 console.warn。
- 后果：HTTP 失败可被当作已走完停止路径；本地不再显示输出不证明远端已停。远端是否继续执行为 **Inferred，未发送真实停止请求验证**。
- 改法：区分“请求停止”“已确认停止”“未能确认，已停止本地接收”；失败可重试并保留当前内容；背景任务的取消另走自身接口。

**TRUST-01 · 顶部名字可能指向 Town 身份而非正在对话的 Being — High／M**

- 位置：B01、K02；证据 E11。名称取 town.displayName || settings.being；Town 配对本身有独立身份与 generation。
- 后果：当两者不一致，主空间身份标签与实际对话目标可能不同。**条件分支已确认；当前用户是否恰好配对两个身份未查询私人配置。**
- 改法：全局姓名只来自当前对话连接及其真实名称；Town 区域独立标出当前配对身份。代发动作显示发送身份及目标；保留现有换身份清理保护。

**ERR-02 · 聊天摘录的“回来源”使用了不匹配的 ID — Medium／M**

- 位置：D09；证据 E12。引用记录 chat:message-…；回来源将 message ID 交给 beings:search-jump；ChatIndex.jump 只按 turn ID 查询，而 runtime 为 message 和 turn 分别生成 ID，Being 回复也没有提问 turn ID。
- 后果：该聊天来源路径可能静默不定位。**ID 不匹配由源码确认；此处纠正此前“引用均可回来源”的过宽描述。** Town 的局部快照返回是另一条路径。
- 改法：提供按消息 ID／持久 seq 与 scene_id 定位的专用桥；未加载时先取相应历史；失效则说明能回到哪个范围，不能静默无动作。

**FBK-03 · “完成已读”依赖 view 名称，与三栏实际可见性脱节 — Medium／M**

- 位置：C01、D06、N05；证据 E13。场景 done 标记仅在 view === chat 时清除；右侧打开 mail 时，中间聊天仍可见，但 view 已是 mail。Town 新动态又通过加载成功推进 seen。
- 后果：显示完成、已加载、真正读过与对方已读缺少统一定义；存在看见回复后侧栏仍提示的条件。实际注意力和阅读位置无法从 view 值推断。
- 改法：按中间场景是否可见、窗口是否活跃、消息是否进入阅读范围定义本地已读；Town“新动态”维持自己的更新语义，不伪造外部已读回执。

### 设计与文档一致性

**DS-01 · spec、demo、现有客户端与旧流程文档混用了不同完成状态 — Medium／M**

- 位置：A03、C08、M02、N02 及物件／搁置设想；证据 E14。正文 spec 默认 17 与当前设置重置 15 不同；workspace-home 仅被 demo 引入；旧场景文档描述全部范围只读，当前发送仍归当前场景。隐私面板另有静态路线图。
- 后果：把“预览里能点”“源码有组件”“客户端已接通”“后端具备能力”混为一谈，会继续做出用户实际用不到的设计。
- 改法：后续每项标记“当前功能／客户端部分接入／仅 demo／需接口”；更正过时文档，设置默认值与 spec 对齐时核对用户已保存偏好。当前隐私事实与未来计划分开。

## 9. 与最新 spec 的合并、修正和参考

### 9.1 保留与补全

| spec 要点 | 本次取舍 | 适用边界 |
|---|---|---|
| 安静、文字主导、中性灰阶、系统字体 | 保留，统一进入所有消息、文档、列表、表单及系统状态 | 安静不等于藏必需入口，也不等于每个面板减少为同一种空白布局 |
| 首屏只讲“我们聊到哪” | 冷启动可用真实摘录与一条真实未读；暖返回恢复工作现场 | 当前尚未接入冷启动数据与恢复契约，不先造一张欢迎海报 |
| 消息不逐条卡片化 | 保留；中央可有一个柔和内容面边界 | 用户要求的整块中央圆角与“消息无卡片”不冲突；不为每段话再包描边 |
| 存在标记四态 | 作为姿态视觉，保留未知与过期边界 | 不能把队列、执行、等待回答、失败、停止等工作状态全部压成四个点 |
| 可信的呼吸与流动 | 只接真实事件、明确过期；减弱动态时静态文字可读 | 当前没有充分事件证据就保持未知；不由 SSE 连通推断 idle |
| 正文 17、最大阅读列 680、辅助文字对比度 | 作为新组件起点；与现有字号偏好统一 | 需在真实字号、亮暗、中文长文、代码和窗口缩放中校验，不能只算色值即验收 |
| 场景抽屉、物件、搁置 | 保留方向，另定义真实数据与恢复行为 | 当前只有 demo 体验；不得把它们列为已有服务能力或自动写入 Being 记忆 |
| 删不必要工具条、默认折叠细节 | 保留；每个内容面只保留当下需要的主要动作 | 全局入口仍可找，信息状态不只 hover 可读，操作结果不只短暂 Toast |
| 375／1440 两档 | Web 与 Desktop 分开验证 | Desktop 先按原生最小 920×640、常用宽度及大字号验收；375 属于 Web 路径 |
| 暂停／继续 | 先确认真实服务能力 | 当前只存在停止路径；不画无法续接同一次生成的控制 |

### 9.2 真实软件参考取机制，不拼外观

本次查阅官方资料，以流程问题选参考；“前沿”不等于复制动效、玻璃或更多卡片，也不声称哪款软件客观最好。

| 参考 | 可采用的具体机制 | 对本项目的取舍 |
|---|---|---|
| [Apple HIG：Modality](https://developer.apple.com/design/human-interface-guidelines/modality?language=_1) | 模态用于有明确收益的短任务，退出路径明显，不在里面套完整应用 | 保留短审阅；Town 写作、长安装和等待配对脱离全局模态 |
| [Dia：对话中的上下文](https://www.diabrowser.com/release-notes/1-6-0-conversations-context-chat) | 使用过哪些上下文、打开了哪些内容能被看见与核查 | 一起看显示来源和快照；Being 是否读过需真实回执，不能仅因用户打开就声称它看见 |
| [Dia macOS 更新记录](https://www.diabrowser.com/changelog/mac) | 分屏各自保留导航控件；后退／前进利用保留的页面状态；过程支持展开 | 主对话仍固定中间；右侧自己负责阅读历史，操作进展紧邻对应对象 |

此前记录的 Linear／Craft 可继续作为视觉候选参考，但本轮没有把它们的局部外观当作整个 Being 产品结构。进入 UI 实作时要给出具体参考画面、采用点和实际对照，不能只写品牌名。

## 10. 所有面板共用的设计细则

### 10.1 每类入口放在哪里

| 空间 | 常驻内容 | 按需展开 |
|---|---|---|
| 顶部 | 当前 Being 名称、明确的场景／内容位置、必要的窗口操作 | Being 菜单里分组放 SBS、连接与本机能力、设置、帮助、更新、退出；下载时出现真实进度 |
| 左栏 | 场景列表、当前项、新建和收起入口 | 绑定、排序、批量、重命名、移除、信息；搁置在真实实现后成为稳定入口 |
| 中间 | 对话、输入、发送目标、需要处理的当前状态 | 引用展开、工具过程、后台任务、查找；不重复铺一排 Town 栏目 |
| 右侧 | 当前栏目／对象标题、后退、收起、当前内容的主要动作 | 栏目选择器、筛选、详情、成员、来源、高级参数；浏览器模式替换本区内容 |
| 设置 | 清楚的分类、当前路径、可返回的子页 | 高级配置、诊断、原始日志；只在用户选择时展开 |

Town 栏目选择器完整保留：篝火、围炉、私信、花园、书架、卷轴、工具库、通讯录、公告／小镇目录。打开任何一项都不改变主对话场景。工具库内部有 Grove 与本机两个清楚位置；“浏览器”进入同一个右侧容器，不再追加主栏。这是导航重组目标，不是删除现有能力。

### 10.2 视觉与内容尺度

- 主对话是稳定阅读面，右侧有内容时两者各有明确边界；中央整块圆角先沿用试验的约 14px、外留 8–12px，待真实客户端检验。页面、弹层、输入框按层级使用统一半径，不给每个元素同一个大圆角。
- 正文以内容为主；标题、作者、时间、范围与状态有稳定阅读顺序。消息用间距和排版区分，文档保持长文节奏，工具详情先讲能力和条件，参数后展。
- 图标统一线宽、尺寸和光学对齐；信息入口常驻且有可访问名称，热区大于图形本身。hover 只加强反馈，不能决定用户是否发现功能。
- 主要动作每个任务区域只有一个；取消、返回、关闭各有语义。危险操作保留范围与现有保护；无新风险时不新增重复通用确认。
- 输入框不会在流式更新、跨栏加载时跳高抢焦点。中文输入组合阶段、选择文字、粘贴、多行编辑、拖文件全部视为主流程。
- 亮暗使用同一信息层级，字色、分隔、禁用、hover、焦点分别检验。字号增大不裁剪收件人、错误和按钮；长 ID／URL／代码局部横向滚动。
- 只有必要的开合与位置过渡，建议上限 150ms；正文每个流式块不重复进场。存在动效只有确有来源时出现，窗口隐藏／失焦按 spec 暂停装饰动效。

### 10.3 所有面板必填的实现单

每个 A01–N07 单元实施前填一份短记录，避免做到某个页面才临时猜规则：

1. 从哪些入口来、正在处理哪个身份和对象。
2. 加载、空、无匹配、无权限、旧内容、失败分别显示什么。
3. 哪个输入何时保存，提交目标是什么，能否重复、能否取消。
4. 什么情况叫完成，部分完成和结果未知怎么继续。
5. 返回、关闭、收起、切场景、换身份、刷新和重启分别保留什么。
6. 键盘顺序、快捷键、Esc 层级、关闭后焦点；亮暗、最小窗口、大字号和长内容。
7. 需要真实服务事件还是只有示例；验收证据来自源码、demo 或真实客户端。

## 11. 实施顺序与验收矩阵

下面是依赖顺序，全部模块都在范围内。第一轮局部源码改动作为试验保留，不能用它替代本计划。后续每批包含真实组件、实际流程、失败恢复、视觉对照与用户反馈；不等到最后一批才处理空态和键盘。

| 顺序 | 完整工作包 | 覆盖范围 | 验收门槛 |
|---|---|---|---|
| 1 | 保护工作与表达真实状态 | ERR-01、FBK-01、FBK-02、TRUST-01、ERR-02；B、C、D、K | 普通草稿／引用重载可恢复，保存失败不丢内容；排队可见可取消；停止有响应判定；身份与来源正确 |
| 2 | 统一空间、导航与覆盖层 | NAV-01–04、FBK-03；A、B、C、L、N07、所有右侧页 | 一个右侧容器；后退／前进／返回目录／收起一致；搜索和设置不清阅读；原生浏览器与浮层正确遮挡 |
| 3 | 完整交流与身份流程 | FLOW-01、FORM-01；E、F、J03–04、K、N05 | 私信／围炉／篝火可同时讨论与写正文；委托有真实阶段；配对后续接但不自动发布；通知回来源 |
| 4 | 完整阅读与知识流程 | G、H、J01–02、D09 | 种子关系、经验墙、分段文档、公告连续往返；过滤与位置恢复；引用有来源及有效范围 |
| 5 | 完整本机能力流程 | I、M04、M06–M08、FLOW-02 | Grove→审阅→安装→本机→来源闭环；导入／删除／失败恢复；本机文件、依赖与已注册工具状态分开 |
| 6 | 设置、Being 入口与生命周期 | M01–M06、B02–03、N01–06、A01–03 | 分类与子页返回；保存时机和影响清楚；SBS 状态可信；更新／退出保护工作；隐私事实与计划分开 |
| 7 | 接入仍缺的连续性能力 | spec 的冷启动摘录、真实存在事件、共同物件和搁置 | 明确数据模型及接口后接线；跨重启恢复、撤销与身份隔离可验证；无能力时不伪装已完成 |

**可先落地的局部修正：**修复聊天来源跳转（ERR-02）；呈现已有队列提示与取消（FBK-01）；把查找结果改为只定位中间（NAV-04）；全局名字绑定对话身份（TRUST-01）。这些不依赖整套视觉重构，但都需要针对对应行为验证，不是只替换文案。

完整视觉检查贯穿 1–6：初始／加载／空／失败／部分成功／未知结果，亮／暗，默认／最大字号，920×640／常用桌面／宽屏，键盘／鼠标／中文输入，长消息／长名称／多附件。每条流程还要验证切场景、换身份、收起再开、断线后恢复。并非把这些组合全称为已测；验收时记录实际覆盖。

## 12. 应保留的能力与待验证边界

### 已有基础应保留

- 场景 runtime 已能隔离草稿和任务；发送内容有快照，跨场景任务不应被视觉改造破坏。
- Town 读写有身份 generation 保护、部分失败提示和输入保留；本地 Kit 删除已有具体确认。
- 引用已与文字／附件分离，第一轮加入引用不直接发布；需要补持久化及来源定位，不必推翻这一正确方向。
- 本地队列已有“不确定不自动重发”的保护；现在应把它完整呈现给用户。
- 原生窗口、CodeMirror、系统快捷键、已有诊断与更新阶段值得沿用；没有证据要求换框架或重做全部后端。
- 搜索已有范围提示、安装结果已区分文件与可用性、SBS 有未知与回执处理；不能为了制造问题而将这些说成完全缺失。

### 明确尚未确认的部分

| 待验证 | 为什么不能从代码直接下结论 | 下一次如何取得证据 |
|---|---|---|
| 全客户端实际观感与布局 | 当前没有完整原生运行截图；CSS 数值不等于渲染结果 | 屏幕访问可用后，在同一日常客户端逐面板查看；不更换 profile 绕过 |
| WebContentsView 遮挡、输入与焦点 | 原生视图和 iframe 跨表面行为 | 浏览器＋模型设置＋原生对话框组合实测；检查缩放、拖宽、最小窗口 |
| 中文 IME、读屏与系统快捷键 | 代码保护和 aria 属性不等于输入或读屏验收 | 实机组合输入、VoiceOver／键盘走 P03／P05／P15 |
| Heart 生命周期、停止与外部委托回执 | Desktop 接口调用不能证明服务端真实执行语义 | 明确接口返回与事件契约；在可控数据上验证，不在用户账户随意代发 |
| 浏览器完整内容共同阅读 | 当前没有统一网页摘录与授权契约 | 明确选择范围、正文提取、来源与过期；接入前不显示“Being 已看见” |
| 物件／搁置和完整全历史搜索 | 当前仅 demo 或能力设想 | 定义存储、身份归属、服务接口与恢复行为，再实施 |
| 用户常用栏目排序与频率 | 功能存在不代表使用频率 | 先保留全部入口；在可操作原型上观察实际任务，不凭想象删除或强排 |
